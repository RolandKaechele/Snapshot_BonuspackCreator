== Plugin System

Drop plugin packages or `.py` modules into the `plugins\` folder (already present, empty, next to the application executable).
Each plugin must expose a `register(app)` function.
The application loads plugins automatically at startup.

See `plugins\README.md` for a minimal example.

NOTE: The `plugins\` folder sits beside `src\` in a source checkout, or beside `SnapshotPackCreator.exe` in a frozen install — see <<frozen-vs-source-example>> below. *Tools → Open Plugins Folder* (in Manage Plugins) always opens the right one.

[[frozen-vs-source-example]]
=== Example: Where Plugins and Assets Live

Source checkout (running via `cli.bat` / `venv\Scripts\python.exe src\main.py`):

[source]
----
snapshot_pack_creator\
├── src\
│   ├── main.py
│   └── assets\                   ← built-in game assets
└── plugins\
    └── my_plugin\
        ├── __init__.py
        └── requirements.txt
----

Frozen install (installer `.exe` or `scons`-built `dist\` folder):

[source]
----
SnapshotPackCreator\
├── SnapshotPackCreator.exe
├── install_plugin_deps.bat        ← installs a plugin's requirements.txt, see below
├── tools\
│   └── python\                    ← bundled Python used by install_plugin_deps.bat
├── _internal\
│   └── assets\                   ← built-in game assets
└── plugins\
    └── my_plugin\
        ├── __init__.py
        └── requirements.txt
----

In both cases you install a plugin the same way — copy its folder into `plugins\` — only the parent folder's location differs.

=== Installing a Plugin

. Unzip (or copy) the plugin folder into `plugins\` so that it sits next to
  the existing plugin folders, e.g. `plugins\my_plugin\`.
. If the plugin ships a `requirements.txt`, install its extra dependencies.
  How you do this depends on whether you're running from a source checkout
  or a frozen install:
+
--
*Source checkout* — install into the application venv as usual:

[source,bat]
----
venv\Scripts\python.exe -m pip install -r plugins\my_plugin\requirements.txt
----

*Frozen install* — use the `install_plugin_deps.bat` helper that ships next to
`SnapshotPackCreator.exe`. It runs a Python bundled in `tools\python\`
(the exact Python 3.12 build used to freeze the app, so there's no
separate Python to install and no version-mismatch risk) and installs the
packages straight into `_internal\`:

[source,bat]
----
install_plugin_deps.bat plugins\my_plugin\requirements.txt
----

WARNING: Only pure-Python packages, or packages with prebuilt `cp312-win_amd64` wheels, can be installed this way — anything else won't be binary-compatible with the frozen app's embedded Python 3.12 runtime.
--
. If the plugin needs local model/data files, follow its own `README.md` for
  where to place them (usually inside the plugin folder itself).
. Restart the application. Use *Tools → Manage Plugins…* to confirm the
  plugin loaded successfully; run with `--debug` for detailed load logs.
. Some plugins (e.g. diffusion backends for the AI Image Generator) only
  become active once their required files are present — the corresponding
  UI elements appear or hide automatically.

=== Enabling and Disabling Plugins

*Tools → Manage Plugins…* lists every plugin found in `plugins\` in a table, one row per plugin:

[cols="1,3"]
|===
| Column | Meaning

| Enabled
| Checkbox — unchecking disables the plugin; it is skipped on the next application start instead of being deleted from disk

| Name
| The plugin's package/module name (matches its folder name under `plugins\`)

| Version
| The plugin's `__version__` string, if it declares one (`—` otherwise)

| Status
| `Enabled`, `Disabled`, `Failed to load` (check `--debug` console output for the error), or `Unsupported Hardware` (the plugin declares a minimum VRAM requirement your GPU doesn't meet)

| Description
| The first line of the plugin's module docstring
|===

Re-check a disabled plugin (and restart) to re-enable it.
The choice is stored in `plugin_config.json` next to `registry.json`.

NOTE: Plugins marked *Unsupported Hardware* (e.g. `moss_image` on a GPU with less VRAM than it needs) have their checkbox greyed out and can't be checked — hover the row for the exact requirement and what was detected on your machine.

Click *Open Plugins Folder* at the bottom of the dialog to open `plugins\` directly in Explorer — handy for dropping in a new plugin or checking an existing one's files without hunting for the folder manually.
