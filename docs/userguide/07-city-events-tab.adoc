== City Events / Beach Events Tab

NOTE: This tab is only visible when the game is set to *Snapshot!*, *Snapshot! Naughty Nightmares*, or *Snapshot: Lewd Shores* on the Pack Info tab, and *Pack Type* is set to *Events* (labelled *Beach Events* in the Pack Type dropdown for Lewd Shores). The tab itself is relabelled *Beach Events* when the selected game is Lewd Shores, and *City Events* otherwise. The game only reads event data from packs declared as event packs; content added while Pack Type is *Photos* would be copied to disk but never loaded in-game.

The tab is divided into three sub-tabs: *Backgrounds*, *Overlays*, and *Dialogs*.
At the top of the tab, choose the *Event Type* — `normal` (default) or `explosion`.

=== Backgrounds

Click *Add…* to open a file picker and choose one or more background image files.
Supported formats: `.png`, `.jpg`, `.jpeg`, `.dat`, `.jpa`, `.pna`, `.bytes`, `.byte` (MP4 video).

The selected image is previewed on the right side of the panel.
Use *▲* / *▼* to reorder backgrounds and *Remove* to delete the selected entry.

=== Overlays

Works identically to Backgrounds — same toolbar, list, and live preview pane.
Overlay images are layered over the background during the event in-game.

Three overlay node commands are available in the Dialogs sub-tab's command table:

* `mod_overlayImage3` — the legacy single overlay slot. Supports static images and MP4 video; only one image/video is shown at a time.
* `mod_overlayImage1` (bottom layer) and `mod_overlayImage2` (top layer) — independent layers that can both be visible at once. Images only (no video support on these two layers). Used by Lewd Shores Beach Events to show, for example, a bottom-of-screen overlay and a top-of-screen overlay simultaneously.

`noOverlayImage` clears all three overlay layers at once.

=== Dialogs

The Dialogs sub-tab has three vertical panels separated by resizable splitters.

==== Build Event

Click *Build Event…* to create a ready-to-edit branched scene with two player choices and a closing `endEvent` command. Choose the scene name, event type, speaker, dialogue, choices, and closing line. The scene receives an unused dialogue ID starting in the pack's ID range.

Choose *explosion* to include the built-in Explosion Lens background, `pulseBackground`, and an optional sound command. A reward photo is optional; when selected, it is added to the Photos tab with Position `event` and the chosen Type and Color, then shown and unlocked by the first choice. The generated scene is selected in the editor so you can continue refining it, its commands, and its graph.

==== Scene List (left panel)

Click *New Scene…* to create a blank scene by name — no file is needed; its content is written out automatically on save/export.
Click *Import Scene…* to import one or more existing `.json` dialog files from disk (each file becomes a named dialog scene in the list).
Any background/overlay image or video referenced by the imported scene's node commands (`showImage`, `mod_showImage`, `showEventPhoto`, `mod_addEventSellablePhoto`, `mod_overlayImage1`, `mod_overlayImage2`, `mod_overlayImage3`) is automatically located beside the source JSON file (same folder, its `Data\` subfolder, or one level up) and added to the Backgrounds/Overlays tabs. A summary dialog reports anything that couldn't be found.
Click *Remove* to delete the selected scene.

Below the toolbar, the *Template* dropdown lists starter scenes bundled in `city_events_templates.json`, filtered to the currently selected game: templates without a `"game"` tag show for every game, and templates tagged `"game": "lewdshores"` (e.g. *Beach Scene Start*, *Beach Dual Overlay Scene*) only show when Lewd Shores is selected.
Pick one and click *Add From Template* to create a new scene pre-filled with that template's nodes; you'll be prompted for a name for the new scene.

Right-click a scene in the list (or empty space below the list) for a context menu with:

[cols="1,4"]
|===
| Action | Effect

| *New Scene…*
| Same as the *New Scene…* button.

| *Import Scene…*
| Same as the *Import Scene…* button.

| *Rename…*
| Renames the selected scene.

| *Delete*
| Deletes the selected scene (same as the *Remove* button).

| *Save As Template…*
| Saves the selected scene's current dialog content as a new entry in `city_events_templates.json`, prompting for a template name and optional description. When the current game is Lewd Shores, the new template is tagged `"game": "lewdshores"` so it only appears for that game; for other games it is saved untagged (visible for every game). The new template immediately appears in the *Template* dropdown.
|===

*Rename…*, *Delete*, and *Save As Template…* require a scene to be selected first, and are omitted entirely when the scene list is empty.

TIP: `city_events_templates.json` lives beside `main.py` in a source checkout, or beside the executable in a frozen build. It holds a plain list of templates, so it can be hand-edited or shared between installs.

==== Node List (middle panel)

Displays the dialog nodes of the selected scene.
Each node shows its index, speaker tag (if any), and a text preview.
A ⚠ warning icon appears before any node whose commands reference an overlay image or sound name that cannot be found among the pack's own assets or the selected game's builtin assets — the same check used by the xref:10b-orphaned-files-tab.adoc[Orphaned Files tab].

Toolbar buttons:

[cols="1,4"]
|===
| Button | Action

| *Add Node*
| Appends a blank node at the end of the scene.

| *Remove*
| Deletes the selected node. Flow references pointing to it are reset to -1; references above it are decremented automatically.

| *▲* / *▼*
| Moves the selected node up or down. All `Next Node`, `Branch To`, and `Action Node` references in the scene are remapped automatically.
|===

==== Node Form (right panel)

Shows and edits the properties of the selected node.

[cols="1,4"]
|===
| Field | Description

| *Speaker*
| Who speaks this line. Common values (`Aya`, `You`, `SKIP`, `Schoolgirl`, `Teacher`, `Trio`, …) are available in the dropdown; you can also type any custom value. Leave blank for narration or system lines.

| *Text*
| The dialogue line shown in-game.

| *Extra Data*
| Advanced field read by the game engine. Leave empty unless specifically required; it is empty in all known bonus packs.

| *Next Node*
| Index of the node to advance to after this one (`-1` = end of chain).

| *Branch To*
| Index of a player-choice set node (`-1` = none).

| *Action Node*
| Index of an action node to trigger in parallel (`-1` = none).

| *Commands table*
| Zero or more commands executed when this node plays. Click the *Command* or *Argument* cell to open a dropdown. Use *Add* / *Remove* to manage rows. A ⚠ icon appears on the Argument cell of any overlay-image or sound command whose value doesn't resolve to a known asset; it updates live as you edit.

| *Browse…*
| Enabled when the selected command uses an image or video argument (`showImage`, `mod_showImage`, `showEventPhoto`, `mod_overlayImage1`, `mod_overlayImage2`, `mod_overlayImage3`, `mod_addEventSellablePhoto`). Opens a file picker; the asset stem name is inserted automatically. If the selected file is an MP4 video (`.byte`), a video player widget replaces the image preview (video preview is only available for `mod_overlayImage3`).
|===

==== Dialog Graph View

Click *Show Graph* (or press the toolbar button) to open the visual node editor in a separate window.
Each dialog node appears as a draggable coloured box; arrows show the three flow connections:

* *Blue (N)* — Next Node (`oNPC`)
* *Yellow (B)* — Branch To (`oSet`)
* *Orange (A)* — Action Node (`oAct`)

Dragging a node updates its stored position, which is preserved in the exported `.json` file.
The graph view and the node list stay in sync because they share the same node list object — edits in either view are reflected immediately in the other.

Hold *Shift* and drag on empty canvas to rubber-band select multiple nodes (a plain drag still pans the view).
With nodes selected, press *Ctrl+C* (or the *Copy* toolbar button) to copy them, then *Ctrl+V* (or *Paste*) to insert duplicates offset slightly from the originals.
Pasted nodes keep their speaker, text, and commands but have their Next/Branch/Action references cleared, so they never silently merge into the existing flow — rewire them manually afterwards.
The *Auto-layout* button re-arranges every node into a top-down flow order based on its Next/Branch/Action connections.

==== Dialog Player

Click *Play…* to open the Dialog Player window.
It steps through the scene node by node, rendering a composite preview of the current background, overlay layer(s), and dialog text box exactly as they appear in-game.
`mod_overlayImage1` (bottom) and `mod_overlayImage2` (top) are drawn together when both are set, underneath the legacy `mod_overlayImage3` slot.
Use the *Next (N)*, *Branch (B)*, and *Action (A)* buttons to follow different flow paths.

=== Export Validation

When exporting, the application checks all dialog scenes for issues:

* *Error* (blocks export): a flow reference (`Next Node`, `Branch To`, or `Action Node`) points to a node index that does not exist, or a scene contains invalid JSON.
* *Warning* (prompts to continue): the last node in a scene has no `endEvent` command, which means the event will not close automatically in-game.
+
The warning dialog includes an *Add endEvent to affected scenes automatically* checkbox.
Checking it before clicking *Yes* appends an `endEvent` command to the last node of every flagged scene in-memory before writing the export, and refreshes the City/Beach Events editor so the change is immediately visible.

TIP: Double-click any background, overlay, or command image preview to open a full-resolution viewer where you can zoom in/out and open the file in the system default editor.
